# Learning and Retention Architecture v10

Use this file to optimize structure for understanding, memory, discrimination, and later review.
It is about organizing directly accessible material for learning, not researching the subject.

## Core aim
A strong output should support:
- first-pass comprehension
- accurate mental organization
- discrimination between similar claims or layers
- later recall
- easy review
- low cognitive load
- ADHD-friendly navigation
- dyslexia-friendly visual and typographic structure

Do not optimize only for pleasant reading.
Optimize for learning without turning the page into a noisy worksheet.

## Simplifier-not-summarizer rule
The default job is to make material easier to absorb without draining it of meaning.

Prefer:
- simplification without substantive loss
- cutting duplication before cutting unique content
- preserving distinctions that change understanding
- preserving control cases that prevent false shortcuts
- preserving operational substeps when they change what the reader can do

Avoid:
- treating shorter as automatically better
- flattening a qualified argument into a one-sided answer
- removing the example that makes the system understandable

## Visual pretraining rule
When the material is abstract, systemic, financial, political, legal, technical, or multi-layered, add a visual pretraining section early.

Good visual pretraining:
- 3 to 4 pictures maximum for first-pass learning
- one idea per picture
- captions that explain the memory job
- no decorative images that do not teach
- no lines/arrows crossing text
- labels inside boxes

Examples:
- debt loop
- K-shaped economy
- power stack
- exit path
- timeline ladder
- evidence ladder

## Inline glossary rule
When the page contains unfamiliar terms, use inline glossary hovers.
This is part of learning architecture, not decoration.

The glossary should:
- define technical terms where they appear
- work in paragraphs, cards, bold labels, and useful headings
- include aliases and multiword forms
- stay inline and not disrupt reading flow
- have a collapsed glossary section as backup

Do not rely only on a glossary at the bottom.
The user should not need to leave the sentence to decode the sentence.

## Adaptive scaffolding rule
Use the lightest scaffolding that makes the material learnable.

Increase scaffolding when:
- concepts are unfamiliar
- multiple layers are easy to confuse
- many names, sources, or terms appear
- the page is likely to be studied later
- the user asks for ADHD/dyslexia support

Use lighter scaffolding when the material is simple.

## Default sequence for dense material
Strongly prefer:
1. **Orientation** — what the page is about
2. **Core thesis / quick answer** — the central idea in direct language
3. **Visual pretraining** — pictures before detail when abstract
4. **Concept primer** — 4 to 5 mental tools, collapsed if optional
5. **Anchor example** — one concrete model case early
6. **Organizing frame** — show the major buckets/layers
7. **Segmented explanation** — one main job per section
8. **Mini recap** — only where it compresses new value
9. **Discrimination support** — compare, contrast, or classify if confusion is likely
10. **Final synthesis** — more precise after the map is complete
11. **Retrieval checks** — answer from memory before revealing cues
12. **Review-later ladder** — short spaced review plan when study-worthy

These are internal functions; reader-facing headings must be subject-specific.

## Concept-primer rule
A concept primer gives the minimum mental tools needed to understand the rest.
It is not a mini-conclusion and not an evidence dump.

Usually answer:
1. What is the exact question?
2. What are the main readings or layers?
3. What counts as strong evidence?
4. What confusion should be avoided?
5. What control point or clarifier prevents overreading?

Keep it to 4–5 blocks unless the topic truly demands more.
Collapse by default if the quick answer and visuals already orient well.

## Anchor example rule
Use one concrete, compact example early when the system is abstract.
The example should make the system usable.

For financial/political topics, a small anchor such as a single bank loan can teach:
- how money enters
- where obligation appears
- why refinancing matters
- how the logic scales upward

## One-idea-one-home rule
Do not repeat the same point unless each repetition has a distinct learning job:
- primer
- anchor
- explanation
- recap
- final synthesis
- retrieval

Invalid repetition: restating the same conclusion in slightly different wording.

## Progressive deepening rule
Each major section should add something new:
- orient
- define
- visualize
- anchor
- organize
- explain
- compare
- synthesize
- retrieve
- review later

Do not loop around the same conclusion too many times.

## ADHD support
Use:
- clear section boundaries
- short paragraphs
- visible memory hooks
- specific headings
- occasional recaps
- collapsible optional supports
- reading controls only if they help
- no giant undifferentiated walls of text

Avoid:
- too many equal-weight cards
- excessive visual variety
- long prose before the first useful answer
- hidden definitions for key terms

## Dyslexia support
Use:
- Comic Sans Latin stack by default
- generous line-height
- warm low-glare background
- consistent cards and spacing
- specific headings
- inline glossary definitions
- no cramped tables
- no text on top of lines/arrows

Avoid:
- tight negative letter-spacing
- small text inside diagrams
- labels outside boxes
- huge all-caps passages
- thin low-contrast text

## Retrieval ladder
For study-worthy material, end with 4–7 prompts.
Move from easier to deeper:
1. core sentence
2. define key term
3. explain anchor example
4. compare two layers
5. apply model to a new case
6. state a caution or limit

Answers may be hidden/collapsible.

## Review-later support
Use short spaced-review cues:
- tomorrow: draw the loop
- three days: explain the anchor example
- seven days: teach the model aloud
- two weeks: apply it to a new case

Keep it short.
It should help the reader return, not become homework clutter.

## Qualified-answer preservation
When the source supports a qualified answer, keep the qualification visible in the body.
Use one counterweight block, comparison row, or caution card when it prevents a common misunderstanding.
Do not let the qualification appear only in the conclusion or source shelf.

## Final learning audit
Ask:
- Can the reader state the core idea in one sentence?
- Is there a picture or anchor for the most abstract part?
- Are technical terms decoded where they appear?
- Are headings specific enough to support scanning?
- Does each section add a new learning job?
- Is the final retrieval section short enough to use?
