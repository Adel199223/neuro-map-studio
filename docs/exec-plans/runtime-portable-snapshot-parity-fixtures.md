## Implementation Notes

The saved runtime map page-state envelope is:

```text
{ kind: "map-workspace", workspace, starterHidden, review }
```

The current map views live in `workspace.pages[]`; `workspace.activePageId` selects the active inner map view. Workspace backup page-state records wrap that data as:

```text
{ id, pageId, pageType, stateVersion, data, createdAt, updatedAt }
```

`runtimePortableSnapshot.ts` should keep helpers pure. It must not import browser runtime modules, use DOM APIs, perform storage reads/writes, or call network APIs. Runtime nodes and relationships should flow through the existing portable snapshot builder, which uses `workspaceCore.normalizeMap`.

Review cards are still generated by `mindmap.js` at runtime. Stage 5A3 preserves persisted review attempts and sessions, and accepts materialized review cards only as explicit helper input for fixtures or future adapters.

The pre-merge hardening passes also verify converted runtime snapshots with the Stage 5A1 review summary and Review Next helpers, confirm conversion does not mutate source fixtures, filter invalid scoped runtime attempts, and preserve missing optional `attemptCount` as omitted through final portable snapshot normalization rather than inventing `1`.
